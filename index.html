GLM v1: ask a knowledge graph, watch it walk

Shannon answers questions by walking a map of facts, and shows you the path it took.

Other demos: Chat (GLM in a chat window) · Pocket (on-device chat) · Shannon QA (ask a document) · Idea model

  1. Find the thingIt spots the name in your question, like “Memento” or “Abraham Lincoln”.
  2. Follow the linksIt picks which kinds of links to follow, like “directed by”, and walks them.
  3. AnswerWhere the walk ends is the answer, like “Christopher Nolan”.

Shannon reads your question with a small frozen encoder, turns it into a chain of relations, and walks a knowledge graph to the answer. Everything runs on this device: the encoder, the scorer and the graph. No server sees your question.

Teach & forget

Teach Shannon a fact (movies pack). It goes into a separate conversation pack that sits beside the movies pack; questions can walk its links straight away. Forget unloads it again, and the fingerprints below show the movies pack was never changed.

Facts are entered with a form; a learned fact-writer from the rung-9 experiments will replace this.

    About this demo

    GLM ("graph language model") is Shannon plus a knowledge graph. The language part is small and frozen; the facts live in the graph, which loads and unloads as a pack. Unloading a pack really removes those facts: ask again and it has nothing to say.

    How an answer is made (movies pack)
    1. The linker finds the longest entity name from the loaded packs in your question (it uses the pack's own entity list, the names in the dataset's graph) and replaces it with a placeholder. 2. MiniLM gives one vector per word piece. A linear tagger turns each into a soft vote over relations, and the votes sum into a 16×16 question operator. 3. Every relation path of 1 to 3 steps that exists from that entity is scored by cosine between the question operator and the product of the relations' 16×16 operators. 4. The best path that reaches something is walked; answers are ranked by how many paths reach them.
    Tiny (movies pack)
    A 9.6k (MetaQA) / 0.2M (WebQSP) parameter trained scorer on a frozen 22.7M MiniLM, about 23M parameters in all (27M with the text-graph builder). That is about 1/900 of gpt-oss-20b's parameters and 1/150 of its active parameters.
    Energy (movies pack only)
    About 0.1–0.2 J per question above idle, batched, on an A40, the same as any MiniLM-sized ranker. That is roughly 65–270× less than gpt-oss-20b answering from the same retrieved facts (GPU only for gpt-oss). This page does not measure energy on your device. No energy claim is made for the general pack in the browser.
    Server energy (lean)
    On one A40, answering 2,000 open Mintaka questions in a batch, Shannon's whole answer path (name lookup, graph walk, scoring; 23M parameters, 0.1M trained) used about 0.12 J per question above the GPU's idle draw (GPU measured, CPU estimated from TDP). Qwen2.5-1.5B closed-book used 0.25 J and Qwen2.5-0.5B 0.14 J, measured the same way on the same pod. Qwen-1.5B is still more accurate (27% vs 23%; Qwen is scored on its text, Shannon on graph nodes). Counting the GPU's idle draw as well, the three are 0.27, 0.40 and 0.26 J. This is a server measurement on the full Wikidata graph (KG mode for Shannon, text mode for Qwen), not a measurement of this page. Method.
    How good it is (movies pack)
    This scorer (seed 0) was trained on MetaQA 1- and 2-step questions only. On a held-out MetaQA set with the topic entity given it scored 0.97 (1-step), 1.00 (2-step) and 0.78 (3-step) hits@1. MetaQA questions are template phrasings, and the held-out set reuses the training templates, so free-form wording can do worse.
    General knowledge pack (Wikidata)
    A 303,149-entity core of Wikidata (the 300k best-connected entities of Wikidata5M plus the entities named in Mintaka's train and dev questions): 3.46M facts between them, 1.04M dates and quantities, 1,089 relations. Facts and labels are Wikidata's (CC0). It is loaded in pieces: about 3 MB to start, then the name index, the facts around the names in your question and their neighbours' relation lists are fetched as needed (a few MB for most questions, more for very connected names such as countries) and kept for later questions.
    How an answer is made: the linker finds candidate names (exact aliases and label prefixes) and a 513-parameter network picks up to three, using MiniLM vectors of the question and the names. Every 1- and 2-step relation path from them is scored against the question (KG16 R0 = KG15's S1-sym scorer: 16×16 operators read from the relation names), and a small head picks one of six answer types: pick a node, count, yes/no, largest, smallest, or compare two named things on an attribute. Nothing is generated and there are no hand-written answer rules.
    How good it is: about 1 in 5 open questions right (Mintaka dev 21.1% (421 of 2,000) with this pack, all 2,000 questions, run file; 22.8% on the full 4.8M-entity graph; Mintaka test 21.4%). Wrong answers are common, and a right answer can come from an odd path: check the path it shows. The examples are Mintaka dev questions it answers right with a sensible path.
    Parity: run in Node on all 2,000 Mintaka dev questions, the browser code gave the same answer type as the Python model on 2,000, the same names on 1,999, the same top path on 1,999 and the same answer on 1,999 (the one answer that differed was a miss in Python too, so the 421 hits are the same). Parity was also checked inside a real browser on the first 200.
    Speed (lean): the page now runs MiniLM once per question for both the linker and the reader (it ran twice before), encodes each candidate name once per visit and without padding, and reuses relation-path products across questions. On all 2,000 dev questions (Node, one WASM thread, 8-vCPU cloud CPU, before and after on the same machine) the median time per question fell from 319 ms to 87 ms and the 90th percentile from 673 ms to 212 ms, with no change in answers (both match the Python model on 1,999 of 2,000, as before; before, after). Downloads did not change: about 21 KB (gzip) per question on average once earlier questions' files are cached, and a median 2.6 MB for the first question of a visit. The server version's retrained linker was tried on this pack and kept out: it finds the right name more often (top-3 recall 71.5% vs 70.4%) but answers 4 fewer questions right (check).
    Limits
    Two packs: Wikidata general knowledge (a research preview, wrong about 4 times in 5; knowledge of a 303k-entity slice of Wikidata, not the whole web) and movies (WikiMovies, about 2016). The linker is plain name matching, so an ambiguous or misspelt name can pick the wrong thing. Answers are graph nodes; nothing is generated. On the movies pack, questions outside the nine relations (directed by, written by, starring, year, language, genre, tags, IMDb votes, IMDb rating) get the nearest path anyway, and teaching works on the movies pack only.
